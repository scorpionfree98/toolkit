# 集成安全检查（2026-11-23）

范围：源码迁入、权限/入口、运行时打包及受控验证。不是完整渗透测试，也未做依赖漏洞数据库全量扫描。没有迁移独立 App 的证书私钥，未使用真实业务请求验收；设备验证边界见 [发行说明](../releases/20261123-stability.md)。

## 已解决

- **发行物私钥样本夹带**：原运行时带 Tornado 的公开测试 `test.key`，不是用户秘密，但不应发行。剔除后重新固定哈希；构建扫描私钥文件名与完整 PEM，异常即失败。来源原始哈希不改写，转换脚本与最终 APK 检查保留。
- **仅源码检查不足**：实际 APK 中 `.gz` 被资产合并器展开并改名。改用 `.bin` 保持压缩字节，最终 APK 必须包含匹配哈希的资产与 ARM64 后端，CI 校验后才能进入原签名发布步骤。
- **入口防护**：捕获界面不导出；Android/ABI 门禁在宿主入口、模块页面和启动服务重用。没有第二个 Launcher。

## 保留并核对的约束

- Shizuku UserService 校验 Binder caller UID；特权操作为固定命令参数数组，不提供任意 shell/路径执行接口。
- 通信桥仅绑定 loopback，每会话随机 token，错误 token 不落盘；请求路径、帧格式和最大体积有检查。对应 JVM 用例通过，未作真机 Binder/端口攻击测试。
- CA 与抓包日志在宿主私有目录。公开证书导出不包含签发私钥；日志导出有 Cookie/票据等敏感信息提示，并排除 CA 与代理所有权配置。
- 签发材料运行时会通过已授权 Binder 交给内核，暂存在 shell 所有的受限目录/会话文件并在停止时清理，不写入 APK/Git。这依赖用户对 Shizuku/shell 权限的信任，不能声称与其他获授权 shell 工具完全隔离。
- 不覆盖既有代理/PAC/VPN；停止/故障仅恢复自己拥有的代理状态。源码与独立版证据不代替合集设备恢复验收。
- 内置引擎继续上游 TLS 校验（`ssl_insecure=False`），宿主没有全局放开明文。BouncyCastle 依赖存在 Lint `TrustAllX509TrustManager` 警告，未据此声称全依赖安全审计通过。
- 原正式签名与密钥注入流程不改。正式发行由 Actions 注入地图 Key 并签名；离线无密钥构建不可代替正式发行包。设备候选包已核对同签名覆盖升级。

## 保留的验收缺口

设备上的权限授权、CA 信任、证书固定、VPN 撤销/冲突、切网、Doze/长时后台、进程故障恢复，以及旧系统工具回归，均需受控设备验收。禁止用真实京东业务请求替代这些测试。
